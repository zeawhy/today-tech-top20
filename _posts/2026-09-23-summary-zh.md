## [GPT-6 Astra 协助破解自 2005 年以来未解的恩尼格玛密文](https://www.cryptocellar.org/bgac/the-mvueh-break.html) ⭐️ 8.0/10

据报道，OpenAI 的 GPT-6 Astra 协助破解了一条自 2005 年以来始终无法解出的历史恩尼格玛密文，相关案例研究由研究员 Leffen 发布在 Frode Weierud 的 CryptoCellar 网站上。解密后的明文大致为：“请说明行军路线。我在 Rosenow，Rosenow。请立即通过无线电回复”，署名者暂读作 Waschbusch。 这一说法引发了激烈争论：AI 在解决长期悬而未决的密码分析难题中究竟应得多少功劳，尤其是据报道 Astra 还自行生成了 Python 和 C++ 的恩尼格玛模拟器软件来辅助破解。这既凸显了大语言模型在历史和科学研究中日益增长的作用，也凸显了区分人类专业贡献与机器贡献的难度。 该密文最终被确认使用 Enigma I、反射器 B、转子顺序 II-V-III、环设置 H-M-F 以及十个插线板配对，并且左侧转子在第 72 个字母处发生了翻转——这是罕见事件，会破坏标准的已知明文攻击。原始转录也存在错误，而且该密文使用了与当天其他通信完全不同的密钥，这正是它长期无法破解的原因。

hackernews · sohkamyung · 9月22日 13:52 · [社区讨论](https://news.ycombinator.com/item?id=49801324)

**背景**: 恩尼格玛是一台机电转子密码机，二战期间被纳粹德国广泛使用；其密文最早于 1932 年被波兰密码学家破解，随后布莱切利园的盟军工作（包括艾伦·图灵的研究）在整个战争期间持续利用它。GPT-6 Astra 是 OpenAI 于 2026 年 9 月发布的大语言模型，而这条密文是 1941 年的一条简短德军通信，自 2005 年以来一直未能被解出。

## [Visual FoxPro 借助全新 Rust/WASM 运行时重获新生](https://foxscript.org/) ⭐️ 8.0/10

一位开发者让微软已于 2007 年停止在版本 9 的 Visual FoxPro 重获新生：他用 Rust 编写并编译为 WebAssembly 的新运行时，并与真实的 vfp9.exe 进行校验。该项目解除了旧版 2 GB 的表大小限制，仍能加载旧的 32 位 .fll 插件，还额外加入了 lambda、JSON 支持和 HTTP 服务器，并以 MIT 许可证发布。 这很重要，因为仍有大量关键业务软件运行在 Visual FoxPro 上，而重写一套已有 20 年历史的应用往往意味着失去业务。一个现代化的跨平台运行时可以让企业继续沿用现有应用，而不必面对高风险、高成本的迁移。 该运行时用 Rust 编写并编译为 WebAssembly，其行为会与原始 vfp9.exe 进行校验，但报表功能尚未实现，且构建产物未签名。旧的 32 位 .fll 插件仍可加载，同时还额外加入了 lambda、JSON 和 HTTP 服务器等新特性。

hackernews · boredjohnny · 9月22日 21:00 · [社区讨论](https://news.ycombinator.com/item?id=49808023)

**背景**: Visual FoxPro 是微软开发的一种以数据为中心、面向对象的编程语言和 IDE，源自 FoxPro 和 FoxBASE，版本 9.0 于 2004 年发布、2007 年更新，微软于 2015 年终止支持。它因让 CRUD（增删改查）开发变得极其简单，而被广泛用于小型企业数据库应用。WebAssembly（WASM）是一种可移植的二进制指令格式，运行在沙箱虚拟机中；Rust 则是一种系统编程语言，常用于构建快速、安全的 WASM 运行时。

DeepSeek-AI 与清华大学联合发布技术报告《DeepSeek Elastic Compute（DSec）》，公开了一个每天服务约 300 万个沙箱实例、支撑大规模智能体训练与评测的沙箱平台。该平台通过统一 SDK 提供 FnCall、容器、Firecracker microVM 和完整 VM 四种后端，并将有状态的 rollout 执行与可抢占的 GPU 训练解耦。 这份报告罕见地披露了大规模智能体训练背后的基础设施层，而多数实验室对此鲜有公开。其架构设计与性能数据可为更广泛的 AI 系统社区在构建强化学习、代码执行和电脑操作智能体的沙箱环境时提供参考。 单个生产单元约 160 个节点，峰值并发超过 38 万个沙箱，创建速度超过每秒 5000 个；单节点可高密度承载 3200 个容器或 800 个 microVM。通过基于 3FS 分布式文件系统按需加载 EROFS 镜像（而非传统 Docker 全量拉取），DSec 实现任务完成时间快 1.7 倍、磁盘写入减少 57%，并借助内存共享与回收机制使峰值内存占用下降约 40%。
